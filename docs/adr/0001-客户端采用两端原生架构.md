# ADR-0001：Windows 与 Android 客户端采用两端原生架构

- 状态：已接受，进入 `v0.3-G0` 前置治理阶段
- 日期：2026-08-23
- 决策者：项目主控；Windows、Android、协议安全、QA/发布四个只读 Agent 交叉评审
- 适用范围：`E:\project\clipshare` 仓库内的客户端扩展

## 背景

项目书第 9 节要求扩展 Windows/Android 客户端，包含托盘、剪贴板、快捷键、系统分享入口、本地历史和设备间同步。现有系统是 FastAPI + Web/PWA + CLI，已经具备匿名文本/文件分享、访问次数、有效期、E2E 加密和流式文件传输，但没有设备配对、同步游标、云端历史或订阅协议。

两端最重要的能力都高度依赖平台：Windows 需要 Win32 剪贴板通知、托盘与全局快捷键；Android 则受后台剪贴板和后台服务政策约束，需要 Sharesheet、SAF、WorkManager 和系统签名/发布链。跨平台 UI 框架仍需要大量原生桥接。

## 决策

采用两端原生实现，共享协议资产而不强制共享 UI/runtime 代码：

- Windows：.NET 10 LTS、C#、WinUI 3/Windows App SDK、MSIX；首发支持仍处于 Microsoft 支持期的 Windows 11 x64。
- Android：Kotlin、Jetpack Compose、Coroutines、Room、WorkManager；`minSdk 29`，实现时使用当期 Google Play 要求的稳定 `compileSdk/targetSdk`，当前计划基线为 API 36。
- 共享：OpenAPI 快照、Problem Details 错误语义、E2E 密文格式、固定密码学测试向量、威胁模型、测试场景和发布策略。
- 不共享：UI、平台生命周期、剪贴板、托盘/快捷键、文件选择器、通知、密钥存储和安装更新实现。

一期只交付当前 `/api/v1` 能可靠支持的显式发送/领取、文件流式传输、E2E 和本地加密历史。自动设备同步属于独立的 `/api/v2` 匿名能力协议，不与一期并行偷渡上线。

## 平台能力边界

Windows 使用 `AddClipboardFormatListener`/`WM_CLIPBOARDUPDATE` 监听变化，使用 `RegisterHotKey` 和 `Shell_NotifyIcon` 的隔离适配层实现快捷键与托盘；不用 Windows Service 访问交互用户剪贴板。自动上传默认关闭。

Android 10 起，普通后台应用不能持续读取前台应用剪贴板，因此不实现项目书字面意义上的后台监听，也不通过默认输入法、无障碍、悬浮窗或忽略电池优化规避。Android 入口是应用前台显式粘贴、`ACTION_SEND` Sharesheet、SAF 文件流和用户触发同步。

## 被否决的方案

| 方案 | 不采用的主要原因 |
|---|---|
| .NET MAUI | 能共享 C# 与部分 UI，但托盘、快捷键、Windows 剪贴板、Android Sharesheet/后台约束仍需大量平台代码；故障定位和平台测试边界更复杂 |
| Kotlin Multiplatform + Compose Desktop | Android 适配优秀，但 Windows 托盘、Win32 集成、MSIX 和 Windows 原生可访问性仍需额外桥接；增加 JVM/Compose Desktop 发布面 |
| Flutter | 两端系统能力依赖平台通道和第三方插件，插件供应链、版本兼容和企业审计成本较高 |
| Electron | Chromium/Node 运行时体积、内存占用和攻击面与“极简客户端”目标不匹配 |
| Tauri | 体积较好，但引入 Rust、WebView 与移动端插件三套知识面；当前团队和仓库没有该技术基线 |
| PWA/WebView 包装 | 无法可靠提供 Windows 托盘/全局快捷键，也不能突破 Android 后台剪贴板限制；已有 PWA 可继续作为轻量入口，但不能替代原生客户端 |

## 后果

正面影响：平台能力清晰、官方测试工具完整、第三方桥接更少、发布和安全审计可分别收敛；Android 不会因追求“功能对称”而违反隐私政策。

代价：维护两个客户端工程；共享逻辑要通过协议和跨语言测试向量保证一致，而不是靠复用一份代码。CI 需要 Windows 与 Android 两条流水线，开发顺序必须遵守单实现 Agent 串行写入。

## 复审触发条件

只有在以下条件之一成立时才复审本 ADR：

- WinUI 3 或 Jetpack Compose 的支持状态发生重大变化；
- 客户端功能退化为纯表单，不再依赖托盘、快捷键、Sharesheet 或平台密钥存储；
- 有经过 POC 和企业审查的跨平台方案，能显著减少总代码且不增加权限、插件和发布风险。

复审必须新增 ADR，不得直接覆盖本记录。

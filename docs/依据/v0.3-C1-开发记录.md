## 1. 当前工作树已实现

- API 契约版本 `1.0.0`、稳定 operationId、`x-clipshare-consumes-view` 和
  `x-clipshare-auto-retry`；
- `/api/` 成功与错误响应统一 `Cache-Control: no-store`；
- 错误响应统一 `application/problem+json`，保留 405 `Allow` 与 429 `Retry-After`；
- API 时间固定为六位微秒、带 `Z` 的 RFC 3339 UTC；
- `POST /shares` 与 `POST /files` 支持 8–128 位 `Idempotency-Key`：数据库只保存
  key/request SHA-256，PostgreSQL transaction advisory lock 串行化同键请求，业务资源与
  幂等结果同事务提交，同键异请求返回 409；过期记录采用索引、有界 `SKIP LOCKED`
  机会式清理；
- 文件上传在同一次 64KiB 流式落盘中计算 SHA-256，重放上传确认请求指纹后删除本次
  临时文件，不产生第二个资源；
- ENC1 冻结为 AES-256-GCM、32-byte key、12-byte IV、128-bit tag、空 AAD、
  `ciphertext || tag`、严格无 padding Base64URL；服务端流式验证 envelope，并以加密前
  明文 10MiB 和 marker 16MiB 为边界；
- WebCrypto 接入共享已知答案向量，覆盖严格 Base64URL、错误 key、tag 篡改、孤立
  surrogate 与非法 UTF-8；
- 新增版本化 Problem Details 目录、OpenAPI snapshot 测试、UTC/幂等/ENC1 单元与真实
  PostgreSQL 并发集成测试。

以上均为未提交工作树内容；本记录只确认 C1 门禁通过，不代表工作树已经提交，
也不代表 Windows/Android 客户端产品已经达到上线状态。

## 4. 2026-08-24 最终收口结果

- C# 与 Kotlin/JCE 合约项目已实现，并与 WebCrypto 共同消费四个正向向量；新增
  `negative-vectors.json` 作为三端共用的 envelope、Base64URL、认证与 Unicode 负向真源；
- 三端解析器均在拆分/解码前拒绝超过 16 MiB 的 marker；Kotlin 文本编码改为严格 UTF-8，
  .NET/JCE 认证测试只接受各平台明确的 tag mismatch 异常；

## 6. Docker 边界

Docker 被授权作为本项目专用测试沙盒使用，可按需要创建、重建、启动、停止或删除测试
容器与镜像，不必逐步确认。硬边界是不得挂载、覆盖或污染本机项目外数据，不得把测试
连接指向外部/生产数据库或服务，不得执行会影响宿主数据的全局清理。客户端日常测试优先
复用精确名称 `clipshare-test-dotnet` 和 `clipshare-test-kotlin`；Full Gate 继续使用带
run-id 的短生命周期资源并在结束时验证零残留。

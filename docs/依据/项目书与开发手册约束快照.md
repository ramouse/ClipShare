# 项目书与开发手册约束快照

- 快照日期：2026-08-23
- 用途：供 `E:\project\clipshare` 仓库内 Agent 使用，避免 Agent 读取或写入项目目录之外的位置
- 来源：用户提供的《云剪切板分享系统》项目书，以及既有 ClipShare 开发方案/学习手册
- 同步方式：外部原件发生变化时，只能由用户或人工主控审阅后更新本文件；Agent 不得自行访问仓库外原件

## 1. 项目目标

ClipShare 是匿名云剪切板分享系统。基础目标包括文本分享、分享链接/二维码、有效期、访问次数、手机和电脑访问、数据库存储、安全短码、防 XSS、真实部署及完整文档。

客户端属于项目书第 9 节创新扩展，目标平台为 Windows 与 Android。建议能力包括系统托盘、剪贴板变化、快捷上传、云端拉取、本地历史、Windows 全局快捷键、Android 系统分享入口和便捷替换。

项目书的扩展要求是方向提示，不是绕过现代操作系统隐私限制的依据。平台官方能力、安全政策和用户明确授权优先；Android 后台剪贴板监听必须按现代平台限制改写为显式分享/粘贴。

## 2. 既有功能与安全红线

- 完全匿名：无注册登录，不存储真实身份信息，不记录客户端 IP。
- 有效期和访问次数由服务端强制；达到限制后禁止访问。
- 分享 ID 使用安全随机短码，禁止自增可猜测 ID。
- 用户内容必须防 XSS；富文本渲染必须消毒。
- E2E 密钥只在客户端持有，不上传服务器；服务器只存密文。
- 文件上传/下载必须流式，限制大小，防路径遍历，异常时清理半成品。
- 密钥和环境配置不得入库；生产只开放必要端口，数据库不得暴露公网。

## 3. 企业工程标准

- 清晰分层、强类型、静态检查、格式化和严格编译告警。
- Conventional Commits；`type` 使用英文，subject/body 使用中文，提交可追溯。
- 单元、集成、E2E 三层测试；核心逻辑覆盖率至少 90%。
- CI 按静态检查/测试/构建顺序设置强制门禁；失败不得发布。
- 结构化日志、健康检查、速率限制、安全响应头、环境变量密钥、可回滚部署。
- 代码、API、部署、开发心得、贡献说明、演示脚本和学习材料同步交付。

## 4. 多 Agent 流水线

- 主控负责模块拆分、接口冻结、权限、验收和提交，是唯一可提交者。
- 同一时刻最多一个实现 Agent 写业务代码；实现 Agent 只能写明确范围。
- 安全/QA 审查 Agent 只读，输出问题清单，不直接修复。
- 每个模块执行：实现 → 对抗性审查 → 修复 → 沙盒验证门 → 文档同步 → 主控提交。
- 模块间严格串行；前一模块未通过门禁，不启动依赖模块。
- 接口契约先行；变更接口必须同步方案、OpenAPI、代码和测试。

## 5. 测试隔离要求

既有手册强调容器内验证，但本次审计确认“容器化”不足以证明数据隔离：现有开发 Compose 使用持久卷，集成夹具会清表。因此客户端扩展采用更严格规则：

- 所有测试在独立、一次性沙盒运行，不连接生产或开发数据。
- 测试数据库、文件存储、网络、端口、构建缓存、模拟器和临时证书均按 run-id 隔离并在结束后销毁。
- 破坏性夹具必须在执行前验证 test 环境、`_test` 数据库名和沙盒令牌。
- 普通测试使用 mock/fake，不读取真实系统剪贴板，不安装永久证书，不访问公网。
- Windows 原生系统测试进入一次性 Windows Sandbox/临时 VM；Android 系统测试进入可丢弃 Emulator。

具体可执行标准以仓库根 `AGENTS.md` 和 `docs/客户端开发实施方案.md` 为准。

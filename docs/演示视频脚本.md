## 分镜 1：开场（00:00–00:30）

**画面**：标题卡「ClipShare — 轻量级云剪切板分享系统 · 比特工场 2026 暑期项目」，切换浏览器打开首页。

**口播稿**：

> 大家好，这是我们小组的作品——ClipShare，一个轻量级的云剪切板分享系统。它的使用场景特别简单：有时候你想把一段文本、一段代码从电脑发到手机上，或者发给同学，微信传来传去很麻烦，ClipShare 就是干这个的：打开网页、粘贴内容、生成一个链接和二维码，任何设备打开就能取走。它完全匿名、不需要注册，还带有效期和访问次数控制。我们给它加了两个自研创新点——端到端加密分享和命令行工具，后面会重点演示。先看核心功能。

---

## 分镜 2：核心功能——创建分享（00:30–01:30）

**画面**：创建页（表单）。鼠标操作：在文本框粘贴一段含标题、列表的 Markdown 文本 → 有效期选「7 天」→ 访问次数选「5 次」→ 点「创建分享」。

**口播稿**：

> 我们粘贴一段 Markdown 文本试试。下方有四个选项：有效期有 1 小时、24 小时、7 天和永久四档；访问次数可以限制为 1 次、5 次或者不限。先选 7 天、5 次，点击创建。创建成功，服务器返回了一个六位随机短码的链接——注意这个短码是安全随机生成的，不是自增 ID，别人没法猜。

---

## 分镜 3：核心功能——链接与二维码（01:30–02:10）

**画面**：结果卡片。操作：点「复制链接」→ 展示二维码图片 → 点「打开分享页」。

**口播稿**：

> 创建完结果卡片上给了完整分享链接，一键复制；旁边是二维码，可以扫码分享。注意链接里的 `/s/` 后面跟的就是刚才那个短码。点「打开分享页」——页面会自动识别内容是 Markdown 并渲染成标题、列表，右上角还有创建时间、过期时间和剩余次数三个徽章。

---

## 分镜 4：核心功能——手机访问与内容识别（02:10–02:50）

**画面**：拿起手机（或模拟器）扫码 → 手机浏览器打开分享页，展示内容与电脑端一致的渲染效果 → 切回电脑，演示手动切换「文本 / Markdown / 代码」标签页。

**口播稿**：

> 现在用手机扫这个二维码，手机上直接打开了同一个分享页，响应式布局，看内容体验和电脑端一致。如果你觉得自动识别不准确，页面底部还可以手动切换文本、Markdown、代码三种渲染模式——比如代码片段会自动做语法高亮。说明一下：页面的访问次数只有真正读到内容才消耗，打开页面本身不计数。

---

## 分镜 5：核心功能——有效期与次数限制（02:50–03:30）

**画面**：新建一条「仅 1 次」的分享 → 打开 → 刷新/再次打开 → 展示 410 错误页「分享访问次数已耗尽」。再打开一条已过期分享（提前准备过期数据或演示错误页）→ 展示「分享已过期」错误页。

**口播稿**：

> 再看两个限制是怎么生效的。我们建一条"仅 1 次"的分享，第一次打开正常，第二次再打开——被拒了，页面显示"分享访问次数已耗尽"。这个限制是在数据库层原子判定的，高并发下也不会出现超卖。同理，过期的链接打开会显示"分享已过期"。错误信息都是统一的友好页面，而不是一个报错白屏。

---

## 分镜 6：创新点 A——端到端加密完整链路（03:30–04:40）

**画面**：创建页勾选「🔒 加密分享」→ 粘贴一段敏感文本 → 创建 → 结果链接末尾出现 `#k=…` → 打开分享页显示「已端到端解密」→ 打开浏览器开发者工具 Network 面板，展示请求体里是 `ENC1:…` 密文 →（可选）终端 `docker compose exec db psql` 查数据库，展示落库也是密文。

**口播稿**：

> 下面演示第一个创新点：端到端加密分享。我们勾选"加密分享"，粘贴一条敏感内容，创建。注意看结果链接的末尾多了一截——`#` 号后面是密钥。这个密钥只存在于浏览器里，它所在的 fragment 部分按协议不会随 HTTP 请求发给服务器。打开分享页，内容正常显示，左上角多了个"已端到端解密"的绿色徽章。关键证据在这里：打开开发者工具看刚才的创建请求，请求体里的内容是一串 `ENC1:` 开头的密文——服务器从头到尾只见过密文，明文只在你自己的浏览器里出现过。算法是浏览器原生的 AES-256-GCM，零第三方依赖。如果链接里的密钥丢了，页面会明确提示"密钥缺失或错误"，不会解出乱码。

## 分镜 7：创新点 B——CLI 工具（04:40–05:30）

**画面**：终端窗口。操作：`clipshare send "跨设备同步测试" --expiry 1h` → 输出链接 → `clipshare get <短码>` → 输出原文 → 演示 `clipshare get https://.../s/xxx`（整链接也可）→ 演示错误码：`clipshare get zzzz99` 显示友好错误、`echo $?` 显示退出码 1；`clipshare send`（缺参数）退出码 2。

**口播稿**：

> 第二个创新点：命令行工具。如果你在终端里工作，根本不用开浏览器——`clipshare send` 直接发，一行命令把内容变成分享链接；`clipshare get` 直接把内容拉回终端，传短码或者完整链接都行。它还支持 `@文件名` 直接发文件内容。退出码是有约定的：0 成功、1 网络或 API 错误、2 参数错误——脚本调用时可以精确判断发生了什么，比如查一个不存在的短码，退出码是 1。终端和网页走的是同一个 API，双端共享。

---

## 分镜 8：系统架构与技术选型（05:30–07:00）

**画面**：架构图（屏幕左侧固定，讲解时高亮对应部分）。文字版架构图：

```
浏览器 ──HTTP──▶ nginx:80/443（反向代理，唯一公网入口）
                    │ proxy_pass
                    ▼
              app:8000（FastAPI · SQLAlchemy 2.0）
                    │
                    ▼
          db:5432（PostgreSQL 16 + Alembic 迁移）
前端：Bootstrap 5 + 原生 JS（marked / highlight.js / DOMPurify）
质量：pytest 92 用例（覆盖率 96%）+ ruff + mypy strict + GitHub Actions CI
```

**口播稿**：

> 介绍一下系统架构。浏览器通过 Nginx 反向代理访问应用，Nginx 是唯一公网入口，负责 TLS 终结、安全头和控制暴露面；后端是 FastAPI，按分层组织——路由层、服务层、领域层和数据层，依赖是单向的；数据库用 PostgreSQL 16，迁移用 Alembic 管理。选型的理由：FastAPI 类型驱动、自动生成 API 文档；PostgreSQL 是项目书推荐的生产级数据库，我们"次数限制不超卖"的并发语义需要真实的数据库行锁；前端刻意选了零构建的原生 JS 加 Bootstrap，部署简单、手机端友好，把资源留给创新点。工程方面是完整的企业级实践：92 个测试、覆盖率 96%，ruff 和 mypy strict 双门禁，GitHub Actions 四阶段 CI（lint、测试、端到端、构建镜像），Docker 一键部署。开发过程我们全程用 Git 管理、Conventional Commits 提交，每次改动都可追溯。

## 分镜 9：安全与隐私设计（07:00–08:00）

**画面**：开发者工具 Network 面板展示安全响应头（CSP / X-Frame-Options / Referrer-Policy / X-Content-Type-Options）→ 终端 `docker compose logs app` 展示日志无 IP 行 → 打开一个含 `<script>` 载荷的分享，展示被消毒、原样显示。

**口播稿**：

> 安全与隐私是我们从需求到代码反复加固的部分。响应层面：所有页面带完整的 CSP 内容安全策略和防点击劫持头；内容层面：用户输入全部走转义或 DOMPurify 消毒，粘贴一个带脚本标签的内容，它只会被当作纯文本原样展示，不会执行——我们有专门的 XSS 冒烟测试验证这一点。隐私层面：项目书要求不记录用户 IP，我们做到了——应用日志不记 IP、限流计数只在内存、生产 Nginx 直接关闭访问日志。密钥不过服务器、日志里看不到任何用户内容。这些特性不是口头承诺，每一条都有测试或者命令可以验证。

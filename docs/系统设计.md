# ClipShare 系统设计文档

> 比特工场 2026 暑期技能提升项目。本文档面向评委与后续维护者，说明系统架构、模块划分与技术选型理由。

## 1. 系统概述

ClipShare 是一个轻量级云剪切板分享系统（pastebin 类）：用户无需注册登录，打开网页粘贴内容即可生成分享链接与二维码，任何设备扫码或打开链接即可获取内容。核心特性：

- 完全匿名（不存储任何个人信息，不记录客户端 IP）
- 有效期控制（1 小时 / 24 小时 / 7 天 / 永久）与访问次数控制（1 次 / 5 次 / 无限），服务端强制
- 内容智能识别渲染（纯文本 / Markdown / 代码高亮 / JSON）
- 端到端加密分享（AES-256-GCM 浏览器加解密，服务器零明文）
- 文件分享（v0.2）：全链路流式上传/下载、E2E 加密文件、文本预览
- 安卓 PWA（v0.2）：可安装、独立窗口、离线壳缓存
- CLI 快速分享工具

## 2. 系统架构

```
                         ┌────────────────────────────────────────────┐
                         │              服务器（Docker）               │
  浏览器/手机  ──HTTPS──▶ │  nginx 反代(唯一入口, access_log off)       │
                         │    │ proxy_pass / X-Forwarded-For 覆盖      │
                         │    │ client_max_body_size 110m / 超时 300s  │
                         │    ▼                                        │
                         │  FastAPI 应用（非 root 容器，uid 1000）     │
                         │    ├─ /api/v1  REST API（JSON）             │
                         │    ├─ /s/{code} 页面 shell + /static 资源   │
                         │    ├─ /manifest.webmanifest + /sw.js（PWA） │
                         │    ├─ 安全中间件（CSP 等安全头/速率限制）    │
                         │    ▼                                        │
                         │  PostgreSQL 16（仅 app 内网可达）           │
                         │  ./data/files 文件卷（上传文件持久化）      │
                         └────────────────────────────────────────────┘
```

**文件分享流式链路（v0.2）**：上传 = 前端 `fetch(File/Blob)` 分块直传（禁 base64 全内存）→
服务端 64KB 逐块落盘 `data/files/` 并计长（超限即断并清理半成品）→ 元数据入库；
下载 = `FileResponse` 流式输出（不整读进内存）；预览 = 头部截断读（≤200KB）。
磁盘文件名由 `secrets.token_hex(16)` 生成，用户文件名仅存元数据（路径遍历无效）。

**PWA（v0.2）**：manifest + Service Worker 离线壳——静态资源 cache-first、
首页 network-first（离线回退缓存壳）、`/s/*` 与 `/api/*` 直连绝不缓存（计数与新鲜度语义）。

**分层架构**（依赖单向：api → services → domain ← db）：

| 层 | 目录 | 职责 |
|----|------|------|
| 表现层 | `app/api/` | 路由、依赖注入、页面 shell；禁止直接访问数据库 |
| 应用服务层 | `app/services/` | 用例编排：创建/读取分享、短码冲突重试 |
| 领域层 | `app/domain/` | 纯业务策略（短码生成/有效期/次数），无框架依赖，可独立单测 |
| 数据层 | `app/db/` | ORM 模型、会话管理、Repository（含守卫式原子自增） |
| 横切关注点 | `app/core/` | 配置、日志、错误模型、安全中间件、时间工具 |

## 3. 关键设计决策

### 3.1 隐私红线（项目书强制，服务端落地）

| 措施 | 位置 |
|------|------|
| 不存个人信息：shares 表仅 7 个字段，无用户/IP 字段 | `app/db/models.py` |
| uvicorn `--no-access-log`，不记录客户端 IP:port | `docker-compose.yml` |
| nginx `access_log off` | `conf/nginx.conf` |
| 速率限制仅内存瞬时计数（不落日志不落库） | `app/core/security.py` |
| 日志只记短码与状态 | `app/core/logging.py` |

### 3.2 并发正确性：守卫式原子自增

"达到次数限制后禁止访问"在并发下不能靠「先判定、后自增」（两请求可同时通过判定突破上限）。实现将判定下推到 SQL 谓词，与自增同一 UPDATE 原子完成：

```sql
UPDATE shares SET view_count = view_count + 1
WHERE id = :id AND (max_views IS NULL OR view_count < max_views)
RETURNING *;
```

返回空即"已耗尽"，杜绝超卖。见 `app/db/repository.py:increment_view_count_guarded`。

### 3.3 XSS 三层防御（前端）

用户内容进入 DOM 仅三条路径，全部消毒：

1. 纯文本 / JSON → `textContent` 赋值（不经过 HTML 解析）
2. Markdown → `marked.parse` → `DOMPurify.sanitize` → `innerHTML`
3. 代码 → `hljs.highlightAuto`（自带转义）→ `DOMPurify.sanitize` → `innerHTML`

配合 CSP `script-src 'self'`（无 `unsafe-inline`）、模板零内联脚本，多层封堵注入面。

### 3.4 端到端加密：服务器零明文

- 加密/解密全部在浏览器完成（WebCrypto AES-256-GCM），API 无感知、后端零改动
- 密文标记格式 `ENC1:<iv_b64url>.<cipher_b64url>`（版本前缀可演进）
- 密钥仅存于分享链接 fragment（`/s/{code}#k=...`）——fragment 不随 HTTP 请求发送，服务器永远拿不到密钥
- 解密后明文仍走 3.3 的消毒管线（加密不绕过 XSS 防御）

### 3.5 其他决策

- **分享短码**：Base62 安全随机（`secrets`），6 位熵 ≈ 35.7 bit；冲突时服务层重试（唯一索引兜底）
- **时间约定**：全链路 naive UTC（应用与 DB 容器均 UTC 时钟），前端解析补 Z 本地化
- **错误模型**：Problem Details 风格 `{type, title, status, detail}`，type 为稳定机器码
- **dev/prod 同镜像**：`INSTALL_DEV` 构建参数区分（dev 可编辑安装+测试工具，prod 最小攻击面）

### 3.6 数据模型：短码中心表与文件表（v0.2）

v0.2 引入文件分享后，短码需要跨文本/文件两种资源唯一，新增三张表：

| 表 | 关键字段 | 约束 |
|----|---------|------|
| `shortcodes` | `code`（主键）、`kind`（`share`/`file`） | 短码**跨类型唯一**的中心登记表 |
| `share_files` | `code` 唯一索引、`original_name`（用户文件名，仅存元数据）、`stored_name`（磁盘文件名，secrets 生成）、`size_bytes`、`content_type`、`encrypted`、`preview_count`、`download_count` + `expires_at`/`max_views`（同 Share 模式） | 业务表 |
| `shares`（既有） | 新增 `code` 唯一索引与 `kind` 语义（经迁移回填） | 业务表 |

创建流程：先向 `shortcodes` 登记 `(code, kind)` 再写业务表，同一事务提交——短码被
任何资源占用时唯一约束冲突，回滚整个事务重新生成短码重试（与既有 `create_share`
冲突重试同构）。读取时按端点查各自业务表：`/api/v1/shares/{code}` 只查 `shares`、
`/api/v1/files/{code}` 只查 `share_files`，数学上无歧义（短码跨表碰撞在 DB 层被排除）。

### 3.7 文件分享关键决策（v0.2）

- **预览与下载共享次数池**：`used = preview_count + download_count`，守卫谓词
  `or_(max_views IS NULL, preview_count + download_count < max_views)` 下推 SQL，
  与文本分享 `increment_view_count_guarded` 同一原子自增模式，并发不超卖；
  元数据读取**不消耗**次数（与二维码同语义，前端双探针依赖此契约）；
- **存储服务唯一写盘入口**：`FileStorage.save_streamed`（64KB 逐块写盘+计长，超限中断
  并自清理半成品）、`read_preview`（截断读）、`delete`（幂等）；`resolve` +
  `is_relative_to` 双重防路径穿越；过期文件访问时**懒删**（元数据读取路径同样承担清理）；
- **字节级加密**：`encryptBytes/decryptBytes`（Uint8Array 输入输出，明文二进制不经过
  字符串层，规避 TextDecoder 对任意字节的损坏）；密文 = `ENC1:` 标记串 UTF-8 字节；
  加密上限 10MB（浏览器全内存加密的固有代价，前端隐藏开关 + 服务端 422 双保险）；
  加密文件不可预览（`preview_available=false` + 端点 415）；服务端磁盘字节级零明文
  （集成测试断言）；
- **全链路流式红线**（用户硬性要求）：服务端禁 `file.read()` 全量读入、前端禁
  FileReader base64 全内存、CLI 文件句柄流式发送 / `iter_bytes` 逐块写盘、
  nginx `client_max_body_size 110m` + 读写超时 300s 配套。

### 3.8 PWA 关键决策（v0.2）

- 静态资源 cache-first（离线可用）、`/` network-first（内容可能变化，断网回退缓存壳）、
  `/s/*` 与 `/api/*` 直连不缓存（访问计数与内容新鲜度语义）；
- `CACHE_VERSION` 版本化 + `PRECACHE_URLS` 手写清单 + `tests/e2e/pwa.test.js`
  逐 URL 断言 200（清单漂移防线）；激活阶段清旧缓存 + `clients.claim`；
- `/sw.js` 由路由下发并带 `Service-Worker-Allowed: /` 头（作用域覆盖全站，否则
  SW 位于 /static/ 无法控制 "/"）；注册脚本为外部文件（CSP `script-src 'self'` 零改动）。

## 5. 技术选型理由

| 选型 | 理由 |
|------|------|
| Python 3.12 + FastAPI | 类型驱动、自动 OpenAPI、生态成熟；学习曲线平缓 |
| PostgreSQL 16 + SQLAlchemy 2.0 + Alembic | 项目书推荐生产数据库；ORM + 迁移符合企业工程标准 |
| Bootstrap 5 + 原生 JS（marked/highlight.js/DOMPurify） | 项目书推荐基础；零构建步骤、部署简单、CSP 友好 |
| Docker Compose（dev/prod 同镜像） | 一次构建到处运行；dev 热挂载 + prod 最小攻击面 |
| 质量门禁（ruff/mypy strict/pytest 三层/CI 四 job） | 企业标准：lint → test → e2e → build 全自动强制 |

## 6. 测试策略

- **单元测试**（`tests/unit/`）：领域纯函数与 CLI（MockTransport），v0.2 新增文件名净化、
  FileStorage 流式/截断/防穿越、file_service 冲突重试/懒删
- **集成测试**（`tests/integration/`）：真实 PostgreSQL + TestClient，含并发原子性、守卫自增防超卖、
  服务器零明文（SQL 直查）、v0.2 文件 API 18 用例（413 无残留/路径遍历攻击/计数语义/加密零明文/短码跨表无歧义）
- **端到端测试**（`tests/e2e/`，Node + jsdom）：浏览器级冒烟（XSS 载荷拦截实测）+ 加密全链路
  + v0.2 PWA 冒烟（manifest 字段契约 + SW 预缓存清单逐 URL 200 漂移检查）
- 全量 155 用例，CI 四 job 门禁（lint → test → e2e → build）

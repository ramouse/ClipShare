# ClipShare 系统设计文档

> 比特工场 2026 暑期技能提升项目。本文档面向评委与后续维护者，说明系统架构、模块划分与技术选型理由。

## 1. 系统概述

ClipShare 是一个轻量级云剪切板分享系统（pastebin 类）：用户无需注册登录，打开网页粘贴内容即可生成分享链接与二维码，任何设备扫码或打开链接即可获取内容。核心特性：

- 完全匿名（不存储任何个人信息，不记录客户端 IP）
- 有效期控制（1 小时 / 24 小时 / 7 天 / 永久）与访问次数控制（1 次 / 5 次 / 无限），服务端强制
- 内容智能识别渲染（纯文本 / Markdown / 代码高亮 / JSON）
- 端到端加密分享（AES-256-GCM 浏览器加解密，服务器零明文）
- CLI 快速分享工具

## 2. 系统架构

```
                         ┌────────────────────────────────────────────┐
                         │              服务器（Docker）               │
  浏览器/手机  ──HTTPS──▶ │  nginx 反代(唯一入口, access_log off)       │
                         │    │ proxy_pass / X-Forwarded-For 覆盖      │
                         │    ▼                                        │
                         │  FastAPI 应用（非 root 容器）               │
                         │    ├─ /api/v1  REST API（JSON）             │
                         │    ├─ /s/{code} 页面 shell + /static 资源   │
                         │    └─ 安全中间件（CSP 等安全头/速率限制）    │
                         │    ▼                                        │
                         │  PostgreSQL 16（仅 app 内网可达）           │
                         └────────────────────────────────────────────┘
```

**分层架构**（依赖单向：api → services → domain ← db）：

| 层 | 目录 | 职责 |
|----|------|------|
| 表现层 | `app/api/` | 路由、依赖注入、页面 shell；禁止直接访问数据库 |
| 应用服务层 | `app/services/` | 用例编排：创建/读取分享、短码冲突重试 |
| 领域层 | `app/domain/` | 纯业务策略（短码生成/有效期/次数），无框架依赖，可独立单测 |
| 数据层 | `app/db/` | ORM 模型、会话管理、Repository（含守卫式原子自增） |
| 横切关注点 | `app/core/` | 配置、日志、错误模型、安全中间件、时间工具 |

## 3. 关键设计决策

### 3.1 隐私红线（项目书强制，服务端落地）

| 措施 | 位置 |
|------|------|
| 不存个人信息：shares 表仅 7 个字段，无用户/IP 字段 | `app/db/models.py` |
| uvicorn `--no-access-log`，不记录客户端 IP:port | `docker-compose.yml` |
| nginx `access_log off` | `conf/nginx.conf` |
| 速率限制仅内存瞬时计数（不落日志不落库） | `app/core/security.py` |
| 日志只记短码与状态 | `app/core/logging.py` |

### 3.2 并发正确性：守卫式原子自增

"达到次数限制后禁止访问"在并发下不能靠「先判定、后自增」（两请求可同时通过判定突破上限）。实现将判定下推到 SQL 谓词，与自增同一 UPDATE 原子完成：

```sql
UPDATE shares SET view_count = view_count + 1
WHERE id = :id AND (max_views IS NULL OR view_count < max_views)
RETURNING *;
```

返回空即"已耗尽"，杜绝超卖。见 `app/db/repository.py:increment_view_count_guarded`。

### 3.3 XSS 三层防御（前端）

用户内容进入 DOM 仅三条路径，全部消毒：

1. 纯文本 / JSON → `textContent` 赋值（不经过 HTML 解析）
2. Markdown → `marked.parse` → `DOMPurify.sanitize` → `innerHTML`
3. 代码 → `hljs.highlightAuto`（自带转义）→ `DOMPurify.sanitize` → `innerHTML`

配合 CSP `script-src 'self'`（无 `unsafe-inline`）、模板零内联脚本，多层封堵注入面。

### 3.4 端到端加密：服务器零明文

- 加密/解密全部在浏览器完成（WebCrypto AES-256-GCM），API 无感知、后端零改动
- 密文标记格式 `ENC1:<iv_b64url>.<cipher_b64url>`（版本前缀可演进）
- 密钥仅存于分享链接 fragment（`/s/{code}#k=...`）——fragment 不随 HTTP 请求发送，服务器永远拿不到密钥
- 解密后明文仍走 3.3 的消毒管线（加密不绕过 XSS 防御）

### 3.5 其他决策

- **分享短码**：Base62 安全随机（`secrets`），6 位熵 ≈ 35.7 bit；冲突时服务层重试（唯一索引兜底）
- **时间约定**：全链路 naive UTC（应用与 DB 容器均 UTC 时钟），前端解析补 Z 本地化
- **错误模型**：Problem Details 风格 `{type, title, status, detail}`，type 为稳定机器码
- **dev/prod 同镜像**：`INSTALL_DEV` 构建参数区分（dev 可编辑安装+测试工具，prod 最小攻击面）

## 5. 技术选型理由

| 选型 | 理由 |
|------|------|
| Python 3.12 + FastAPI | 类型驱动、自动 OpenAPI、生态成熟；学习曲线平缓 |
| PostgreSQL 16 + SQLAlchemy 2.0 + Alembic | 项目书推荐生产数据库；ORM + 迁移符合企业工程标准 |
| Bootstrap 5 + 原生 JS（marked/highlight.js/DOMPurify） | 项目书推荐基础；零构建步骤、部署简单、CSP 友好 |
| Docker Compose（dev/prod 同镜像） | 一次构建到处运行；dev 热挂载 + prod 最小攻击面 |
| 质量门禁（ruff/mypy strict/pytest 三层/CI 四 job） | 企业标准：lint → test → e2e → build 全自动强制 |

## 6. 测试策略

- **单元测试**（`tests/unit/`）：领域纯函数与 CLI（MockTransport）
- **集成测试**（`tests/integration/`）：真实 PostgreSQL + TestClient，含并发原子性、守卫自增防超卖、服务器零明文（SQL 直查）
- **端到端测试**（`tests/e2e/`，Node + jsdom）：浏览器级冒烟（XSS 载荷拦截实测）+ 加密全链路
- 覆盖率 96%（app + cli），CI 四 job 门禁
